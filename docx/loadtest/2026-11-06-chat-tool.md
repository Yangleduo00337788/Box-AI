## 1. 结论

**单路 Tool 调用通；并发未达纯对话 200 路的阈值。**

新建 Agent `k6-tool-agent`，绑定 HTTP Tool `k6_ping`（GET `jsonplaceholder.typicode.com/todos/1`，无确认），模型仅 **`qwen3.8-27b`**，工作台 `POST /conversations/{id}/messages` `stream=true`。检查 SSE `done` 以及 `tool.start` / `tool.end`。

| 规模 | 判定 |
|------|------|
| 1 VU × 20s | **通过**：1 轮，`done` + `tool.start` + `tool.end`，约 21s |
| 50 VU × 2 分钟 | HTTP **0 失败**（未拒连）；SSE `done` **73%**，工具事件 **88%**，checks **85%**，k6 退出 99 |
| 20 VU × 2 分钟（50 VU 之后立刻） | HTTP 0 失败；**0** 次 `done` / 工具事件。迭代约 1.2s，是流里带 `error`，不是容量变好。疑模型在 50 路多轮 tool-call 后额度/限流 |

本机未压 MCP。HTTP 工具打的是公网 JSON，SSRF 不允许 `localhost`。

## 3. 建议

- 带工具的对话不要按纯 SSE 200 VU 验收；本机稳定区间更接近 **个位数～十几路**，50 路已掉 checks。
- 20 VU 那轮不要当对照：紧挨 50 VU，数字被模型侧 residual 污染。
- 现网仍应开对话限流与配额。MCP 见 [chat-mcp](./2026-11-06-chat-mcp.md)。
